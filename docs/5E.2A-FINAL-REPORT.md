## B — 1 Trust Boundary Isolation (Fallback Copy)

**Finding:** Original `storeUploadedFile()` used `copy($tmp, $dest)` as fallback when `$file->move()` failed or when `$file` was array. In production HTTP this would allow arbitrary local file copy (`/etc/passwd` via crafted `tmp_name`) if `UploadedFile::isValid` or `move()` was bypassed. CI4 `UploadedFile::move()` expects `is_uploaded_file` true; fallback silently downgraded to `copy()` even in prod.

**Fix:** Isolated fallback to **testing only**:
```php
public static bool $forceProductionModeForTest = false;
$isTesting = !self::$forceProductionModeForTest && ((defined('ENVIRONMENT') && ENVIRONMENT === 'testing') || getenv('CI_ENVIRONMENT')==='testing');
$isUploaded = @is_uploaded_file($tmp);
if (!$isTesting && !$isUploaded) throw new RuntimeException('Invalid upload: not an uploaded file.');
// ...
if ($isValid && method_exists($file,'move')) { $file->move(...); return; } catch (...) { if (!$isTesting) throw; }
if (!$isTesting) throw new RuntimeException('Failed to store image: move failed and fallback not allowed in production.');
// array branch:
if (!$isTesting) throw new RuntimeException('Invalid file input in production.');
```
MIME validated before storage: `if (!isset(self::ALLOWED_IMAGE_MIMES[$mime])) throw`. Storage root `realpath(FCPATH.'uploads/packages')` enforced.

**Test:** `testArbitraryLocalCopyBlockedInProductionMode` — sets `forceProductionModeForTest=true` and proves `storeUploadedFile($uploadedFileWithNonUploadedTmp)` throws *not an uploaded file*, and `storeUploadedFile(['tmp_name'=>outside])` throws. `testFallbackCopyAllowedInTestingMode` proves testing mode still allows copy via `copy()`. `testStoreSourceCodeContainsTestingGuard` asserts `forceProductionMode`, `is_uploaded_file`, `ENVIRONMENT === 'testing'` remain in source.

## C — 2 MIME Validation (Server-Detected, Not Extension/Client-Type)

**Enforced:**
- `finfo FILEINFO_MIME_TYPE` on `$tmp` (not `getClientMimeType()`/`getClientName()`/browser `Content-Type`).
- `ALLOWED_IMAGE_MIMES = ['image/jpeg'=>'jpg','image/png'=>'png','image/webp'=>'webp']` only; mismatch → `Invalid image type. Allowed: JPEG, PNG, WEBP.`

## F — 7 Path Traversal (Deletion)

**Audit:** Original `deleteStoredFile` used `realpath($full)` and `strpos($relative,'uploads/packages/')===0` but allowed `..` in DB value if file existed via `realFile` check; `is_file($full)` branch checked prefix but not `..`. Also `realpath` returns false for non-existent, then fell through to `is_file($full)` unlink without canonical check.

**Hardened:**
```php
if (strpos($relativePath, 'uploads/packages/') !==0) return;
if (strpos($relativePath,'..')!==false) return;
if (strpos($relativePath,"\\")!==false) return;
$full = FCPATH.$relativePath;
$realUploads = realpath(FCPATH.'uploads/packages');
if (is_link($full)) { $realLinkDir = realpath(dirname($full)); if (strpos($realLinkDir,$realUploads)!==0) return; @unlink($full); return; }
$realFile = realpath($full);
if ($realFile===false) { $realDir = realpath(dirname($full)); if ($realDir && strpos($realDir,$realUploads)===0) @unlink($full); return; }
if (strpos($realFile,$realUploads)!==0) return;
if (is_file($realFile)) @unlink($realFile);
```
DB value `../../.env` or `uploads/packages/1/../../.env.traversal_test` or `uploads/packages/../packages/evil` or mixed `..\\` all rejected before `unlink`.

**Tests:**
- `testDeleteTraversalDbValueBlocked` creates `FCPATH.writable_outside_test_*.txt` and `FCPATH.env.traversal_test`, then calls `deleteStoredFile` with 9 traversal payloads (`../../.env`, `uploads/packages/../../.env.traversal_test`, `uploads/packages/1/../../...`, `../uploads/...`, `uploads/packages/../packages/...`, `../../../../etc/passwd`, `..\\..\\..\\outside.txt`, etc.) → asserts outside files still exist.
- `testDeleteOutsidePrefixNotDeleted` (`writable/...`, `/etc/passwd`, `uploads/other/file.jpg`)

## G — 8 Symlink Safety

**Handling:** `is_link($full)` branch unlinks **symlink itself** after verifying `realpath(dirname($full))` inside `realUploads`, never following to target outside. `realFile = realpath($full)` would otherwise point to outside target; old code `strpos($realFile,$realUploads)!==0` returned early (safe) but then didn't unlink symlink leaving dangling link. New code explicitly `@unlink($full)` (symlink) when link dir is inside root. Non-link path then checked via `realFile` prefix; double-unlink handles case where `$realFile !== $full`.

**Test:** `testSymlinkEscapeNotFollowed` (skips if `symlink` unavailable or FS disallows):
- Creates outside target `sys_get_temp_dir()/outside_symlink_target_*.txt` with `SECRET_OUTSIDE`.
- `mkdir FCPATHuploads/packages/9999`, `symlink($outside, $linkPath)` → `is_link` true.
- `deleteStoredFile('uploads/packages/9999/link_to_outside.jpg')` → `assertFileDoesNotExist($linkPath)` (link removed), `assertFileExists($outside)` (target preserved).
- Re-creates link, deletes again — idempotent, outside still exists.

## I — 10 .htaccess Review (CGI/FastCGI Compatible)

**Before:** 
```apache
<FilesMatch "\.(php|phtml|phar|pl|py|sh|cgi)$"> Require all denied </FilesMatch>
RemoveHandler .php ...
RemoveType .php ...
php_flag engine off
```
Bare `php_flag engine off` causes **500 Internal Server Error** on hosts running PHP as CGI/FastCGI/FPM (no `mod_php`), .htaccess evaluated per-request → images break site-wide.

**After** `public/uploads/packages/.htaccess` (761 bytes, verified via test + `cat`):
```apache
# 5E.2A SECURITY: prevent PHP/script execution inside uploads/packages
# Compatible with mod_php (Apache) and CGI/FastCGI (no php_flag crash)
Options -Indexes -ExecCGI

RemoveHandler .php .phtml .php3 .php4 .php5 .phar .pl .py .pyc .pyo .cgi .sh
RemoveType .php .phtml .php3 .php4 .php5 .phar .pl .py .pyc .pyo

<FilesMatch "\.(php|phtml|phar|php3|php4|php5|pl|py|cgi|sh|exe)$">
  Require all denied
</FilesMatch>
<FilesMatch "\.(php|phtml|phar)$">
  <IfModule mod_php.c>
    php_flag engine off
  </IfModule>
  <IfModule mod_php7.c>
    php_flag engine off
  </IfModule>
  <IfModule mod_php8.c>
    php_flag engine off
  </IfModule>
  <IfModule mod_php5.c>
    php_flag engine off
  </IfModule>
</FilesMatch>

<Files ".htaccess">
  Require all denied
</Files>
```
- Images `200` readable (no blanket `Deny from all`).
- PHP execution blocked via `FilesMatch Require all denied` + `RemoveHandler/Type`.
- `php_flag` wrapped in `<IfModule>` so CGI/FastCGI ignores without 500.
- `Options -Indexes -ExecCGI` prevents directory listing and CGI execution.
- `<Files ".htaccess"> Require all denied` hides config.

**Test:** `testHtaccessPreventsPhpExecutionCompatible` asserts file exists, contains `Require all denied`, `RemoveHandler`, `RemoveType`, **not** `"\nphp_flag engine off\n"` bare, contains `<IfModule` and `php_flag engine off` inside, contains `Options` `-ExecCGI` `-Indexes`, `FilesMatch`.

**Persistence fix:** Both `tests/feature/AdminPackageMediaTest.php` and `PackageUploadSecurityTest.php` `cleanUploads()`/`tearDown()` now rewrite hardened htaccess via heredoc (previously media test wrote legacy bare version and deleted htaccess on teardown leaving `public/uploads/packages/.htaccess` missing — fixed, now 238 suite leaves file intact).

## J — 11 Re-encoding Decision

**Document:** `docs/5E.2A-reencoding-decision.md` (V1 minimal, no large optimization).

**Assessment:** GD re-encoding (`imagecreatefromjpeg/png/webp` → `imagejpeg/png/webp`) deferred for V1. Rationale: server MIME `finfo` + `getimagesize` IMAGETYPE + 5MB + 6000x6000/25M + random filename + htaccess already meets OWASP upload defense for admin-only uploads. Re-encoding would add 30-80ms per image, 3x memory, risk GD libjpeg CVE, degrade quality, require `imagewebp` availability, and is not needed to block execution.

**When to revisit:** If uploads become public/self-service or steganography/metadata threat expands, enable opt-in `config('UploadSecurity')->reencode` flag **after** validation, inside transaction cleanup, preserving size post-re-encode.
